# The Vue Engineering Gauntlet

### Learn Vue by Building, Debugging, Researching, and Shipping

This is not a traditional Vue course.

You will not spend weeks watching tutorials and copying code line-by-line.

This platform is designed to train developers the same way real engineering skills are developed:
through constrained learning, problem solving, debugging, documentation research, and repeated project execution.

The goal is not to memorize Vue.

The goal is to become capable of independently building production-grade Vue applications.

---

# Core Learning Philosophy

Every project follows the same cycle:

## 1. Learn the Core Concepts

Before each project, you are introduced to only the essential concepts required to begin.

Usually:

* 3–5 Vue concepts
* short explanations
* small examples
* minimal theory

Enough to start.
Not enough to avoid thinking.

---

## 2. Research the Missing Pieces Yourself

Real developers constantly:

* read documentation
* search errors
* compare solutions
* debug unknown problems
* discover APIs independently

This platform intentionally trains that skill.

During projects, you will encounter things that were NOT directly taught.

You are expected to:

* search the Vue docs
* investigate errors
* read linked resources
* experiment
* solve problems independently

Helpful documentation links and learning resources are provided throughout the challenge.

---

## 3. Build the Project

Each project includes:

* requirements
* engineering constraints
* expected behaviors
* optional stretch goals

Not:

> “Build whatever.”

But:

> “Solve this engineering problem.”

---

# Every Project Includes

## Project Brief

You receive:

* the product goal
* UI expectations
* behavioral requirements
* technical constraints
* edge cases

Example:

> “Build a Kanban board with drag-and-drop, local persistence, keyboard accessibility, and optimistic UI updates.”

---

# Success Criteria

Every project is evaluated using:

## Required Features

Must function correctly.

## Stretch Goals

Advanced improvements:

* accessibility
* performance
* animations
* TypeScript
* reusable composables
* testing
* caching
* responsive design

## Engineering Constraints

Rules that force better architecture.

Examples:

* no direct DOM manipulation
* no global state abuse
* no duplicated logic
* avoid unnecessary watchers
* separate UI from business logic

---

# Built-In Testing System

Projects are validated automatically using:

* Vitest
* Vue Testing Library
* Playwright

Tests verify:

* functionality
* UI behavior
* edge cases
* accessibility
* async handling
* error recovery

Passing tests means:
your project actually works.

Not:

> “It looked fine on my screen.”

---

# Hint System

Hints are progressive.

You can choose how much help you want.

## Hint Level 1

Small directional clue.

## Hint Level 2

Relevant concept or pattern.

## Hint Level 3

Pseudo-code guidance.

## Hint Level 4

Partial implementation example.

The system encourages productive struggle without leaving you permanently stuck.

---

# AI Engineering Review

After submission, your code receives an AI-powered engineering review.

The AI analyzes:

* readability
* architecture
* composable usage
* state management
* code smells
* maintainability
* unnecessary complexity
* Vue anti-patterns

The goal is feedback.
Not meaningless scores.
